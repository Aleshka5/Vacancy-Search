# 🗄️ Data Models — Vacancy-Search

## 1. Overview

This document defines the domain data models for the Vacancy-Search system. It extends the Data Model Spec in the Master Document (§5) with additional models for agent state management, vacancy lifecycle, and chat semantics.

**Guidelines:**

- Domain models are pure — no SQLAlchemy, no FastAPI, no MinIO references.
- All IDs are `UUID`.
- Timestamps use `datetime` (UTC).
- JSONB fields are used for flexible data (parsed vacancy, agent state, token usage).
- MinIO paths (not content) are stored in DB.

---

## 2. Core Entities

### 2.1 User

Represents an authenticated user in the system.

```python
class User:
    id: UUID
    google_id: str
    email: str
    role: Role = Role.USER
    is_blocked: bool = False
    default_llm_config_id: UUID | None
    created_at: datetime
    updated_at: datetime

class Role(Enum):
    USER = "USER"
    ADMIN = "ADMIN"
```

**Fields:**

- `google_id` — Google OAuth ID (unique).
- `email` — unique.
- `role` — USER or ADMIN.
- `is_blocked` — if True, all API calls return 403.
- `default_llm_config_id` — references `LLMConfig` (nullable; set during onboarding).

**Relationships:**

- One-to-many → `LLMConfig`, `KnowledgeFile`, `LatexTemplate`, `Chat`.

---



### 2.2 LLMConfig

User's LLM provider configuration (API keys encrypted in DB).

```python
class LLMConfig:
    id: UUID
    user_id: UUID
    provider: LLMProvider
    host: str
    api_key_encrypted: bytes
    model_name: str
    is_default: bool
    created_at: datetime
    updated_at: datetime

class LLMProvider(Enum):
    OPENAI = "openai"
    ANTHROPIC = "anthropic"
    OLLAMA = "ollama"
    CUSTOM = "custom"
```

**Fields:**

- `provider` — provider type.
- `host` — API endpoint (e.g., `https://api.openai.com`).
- `api_key_encrypted` — Fernet/AES encrypted bytes (NOT plaintext).
- `model_name` — model identifier (e.g., `gpt-4`, `claude-3-opus`).
- `is_default` — only one per user.

**Relationships:**

- Many → `User`.
- Used by `Chat` as a foreign key (override default).

---



### 2.3 KnowledgeFile

User's Markdown knowledge files (content in MinIO, metadata in DB).

```python
class KnowledgeFile:
    id: UUID
    user_id: UUID
    title: str
    description: str
    minio_path: str
    file_size_bytes: int
    created_at: datetime
    updated_at: datetime
```

**Fields:**

- `title` — human-readable name.
- `description` — used by the Agent for skill-based selection (RAG).
- `minio_path` — path in MinIO (e.g., `knowledge/{user_id}/{file_id}.md`).
- `file_size_bytes` — for validation and display.

**Constraints:**

- Max files: `MAX_KNOWLEDGE_FILES` (ENV, default 10).
- Max length: `MAX_KNOWLEDGE_FILE_LENGTH` (ENV, default 10000 chars).

**Relationships:**

- Many → `User`.
- Consumed by `ContextRetrieverNode` during agent execution.

### 2.4 LatexTemplate

User's LaTeX template (content in MinIO, metadata in DB).

```python
class LatexTemplate:
    id: UUID
    user_id: UUID
    name: str
    minio_path: str
    file_size_bytes: int
    created_at: datetime
```

**Fields:**

- `name` — template name (nullable).
- `minio_path` — e.g., `templates/{user_id}/{template_id}.tex`.

**Relationships:**

- Many → `User`.
- Used by `GeneratorNode` as the base for LaTeX generation.

### 2.5 Chat

A conversation between a user and the agent.

```python
class Chat:
    id: UUID
    user_id: UUID
    title: str | None
    phase: ChatPhase
    llm_config_id: UUID | None
    created_at: datetime
    updated_at: datetime

class ChatPhase(Enum):
    EMPTY = "empty"
    PARSING = "parsing"
    QUESTIONING = "questioning"
    GENERATING = "generating"
    COMPILING = "compiling"
    PUBLISHED = "published"
    ERROR = "error"
```

**Fields:**

- `title` — generated by LLM from vacancy text (nullable initially).
- `phase` — current state of the chat (see §3 State Machines).
- `llm_config_id` — which LLM to use for this chat (overrides default).

**Relationships:**

- Many → `User`.
- One-to-many → `Message`, `Artifact`.

---



### 2.6 Message

Individual messages within a chat (user, assistant, system).

```python
class Message:
    id: UUID
    chat_id: UUID
    role: MessageRole
    content: str
    token_usage: dict | None
    created_at: datetime

class MessageRole(Enum):
    USER = "user"
    ASSISTANT = "assistant"
    SYSTEM = "system"
    AGENT = "agent"  # internal agent messages (not shown to user)
```

**Fields:**

- `role` — who sent the message. `AGENT` for internal messages.
- `content` — text content (can be empty for status updates).
- `token_usage` — JSONB: `{"prompt_tokens": 150, "completion_tokens": 300}`.

**Relationships:**

- Many → `Chat`.

---



### 2.7 Vacancy

Parsed vacancy data extracted from user input.

```python
class Vacancy:
    id: UUID
    chat_id: UUID
    raw_text: str
    parsed_data: dict  # JSONB
    minio_path: str  # raw text in MinIO (if > threshold)
    created_at: datetime

class VacancyParsedData(TypedDict):
    company: str | None
    position: str | None
    tech_stack: list[str]
    hard_skills: list[str]
    soft_skills: list[str]
    requirements: list[str]
    seniority: str | None
    location: str | None
    salary: str | None
    summary: str
```

**Fields:**

- `raw_text` — original vacancy text (also stored in MinIO for large texts).
- `parsed_data` — extracted fields (JSONB).
- `minio_path` — only if text exceeds threshold (e.g., > 10KB).

**Relationships:**

- One → `Chat`.
- Consumed by `GeneratorNode` during TeX generation.

### 2.8 Artifact

Generated document (PDF or TEX).

```python
class Artifact:
    id: UUID

class ArtifactType(Enum):

    COVER_LETTER_PDF = "cover_letter_pdf"
    COVER_LETTER_TEX = "cover_letter_tex"
```

**Fields:**

- `type` — artifact type.
- `minio_path` — e.g., `artifacts/{chat_id}/{artifact_id}.pdf`.
- `file_size_bytes` — for display.

**Relationships:**

- Many → `Chat`.

### 2.9 GlobalPrompt

Admin-managed prompts used by the agent.

```python
class GlobalPrompt:
    id: UUID
```

**Fields:**

- `name` — unique identifier (e.g., `vacancy_parser`).

## 3. State Machines



### 3.1 Chat Phase Transitions

```
  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │  ┌────────┐     ┌──────────┐     ┌────────────┐                 │
  │  │ EMPTY  │────▶│ PARSING  │────▶│ QUESTIONING│                 │
  │  └────────┘     └──────────┘     └────────────┘                 │
  │                      │              │   │                       │
  │                      ▼              ▼   ▼                       │
  │              ┌──────────┐  ┌────────────┐   ┌──────────┐        │
  │              │ ERROR    │  │ GENERATED  │──▶│COMPILING │        │
  │              └──────────┘  └────────────┘   └──────────┘        │
  │                                   │               │             │
  │                                   ▼               ▼             │
  │                              ┌────────────┐  ┌──────────┐       │
  │                              │ ERROR (TX) │  │PUBLISHED │       │
  │                              └────────────┘  └──────────┘       │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘
```

**Transitions:**


| From              | Event                      | To                  |
| ----------------- | -------------------------- | ------------------- |
| EMPTY             | User sends vacancy         | PARSING             |
| PARSING           | Vacancy parsed             | QUESTIONING         |
| PARSING           | Error                      | ERROR               |
| QUESTIONING       | User answers all questions | GENERATED           |
| QUESTIONING       | User requests resume       | GENERATED           |
| GENERATED         | Generator creates TeX      | COMPILING           |
| GENERATED         | Error                      | ERROR               |
| COMPILING         | PDF created                | PUBLISHED           |
| COMPILING         | Error                      | ERROR (TX)          |
| ERROR / ERROR(TX) | User retries               | PARSING / GENERATED |

## 5. Database Schema (SQL)

```sql
-- Users
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    google_id VARCHAR(128) UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    role VARCHAR(10) DEFAULT 'USER' NOT NULL,
    is_blocked BOOLEAN DEFAULT FALSE NOT NULL,
    default_llm_config_id UUID,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_users_google_id ON users(google_id);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);

-- LLM Configurations
CREATE TABLE llm_configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    provider VARCHAR(20) NOT NULL,
    host VARCHAR(255) NOT NULL,
    api_key_encrypted BYTEA NOT NULL,
    model_name VARCHAR(100) NOT NULL,
    is_default BOOLEAN DEFAULT FALSE NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_llm_configs_user_id ON llm_configs(user_id);
CREATE INDEX idx_llm_configs_is_default ON llm_configs(user_id, is_default);

-- Knowledge Files
CREATE TABLE knowledge_files (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,
    description TEXT NOT NULL,
    minio_path VARCHAR(512) NOT NULL,
    file_size_bytes INTEGER DEFAULT 0 NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_knowledge_files_user_id ON knowledge_files(user_id);
CREATE INDEX idx_knowledge_files_minio_path ON knowledge_files(minio_path);

-- LaTeX Templates
CREATE TABLE latex_templates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(255),
    minio_path VARCHAR(512) NOT NULL,
    file_size_bytes INTEGER DEFAULT 0 NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_latex_templates_user_id ON latex_templates(user_id);

-- Chats
CREATE TABLE chats (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(255),
    phase VARCHAR(20) DEFAULT 'empty' NOT NULL,
    llm_config_id UUID REFERENCES llm_configs(id),
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_chats_user_id ON chats(user_id);
CREATE INDEX idx_chats_phase ON chats(phase);
CREATE INDEX idx_chats_created_at ON chats(created_at DESC);

-- Messages
CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    chat_id UUID NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
    role VARCHAR(20) NOT NULL,
    content TEXT,
    token_usage JSONB,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_messages_chat_id ON messages(chat_id);
CREATE INDEX idx_messages_created_at ON messages(created_at);

-- Vacancy
CREATE TABLE vacancies (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    chat_id UUID NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
    raw_text TEXT,
    parsed_data JSONB,
    minio_path VARCHAR(512),
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_vacancies_chat_id ON vacancies(chat_id);

-- Artifacts
CREATE TABLE artifacts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    chat_id UUID NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
    type VARCHAR(30) NOT NULL,
    minio_path VARCHAR(512) NOT NULL,
    file_size_bytes INTEGER DEFAULT 0 NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_artifacts_chat_id ON artifacts(chat_id);
CREATE INDEX idx_artifacts_type ON artifacts(type);

-- Global Prompts
CREATE TABLE global_prompts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(64) UNIQUE NOT NULL,
    content TEXT NOT NULL,
    updated_by UUID REFERENCES users(id),
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT now() NOT NULL
);

CREATE INDEX idx_global_prompts_name ON global_prompts(name);

-- Triggers for updated_at
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_users_updated_at
    BEFORE UPDATE ON users FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER llm_configs_updated_at
    BEFORE UPDATE ON llm_configs FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER knowledge_files_updated_at
    BEFORE UPDATE ON knowledge_files FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER chats_updated_at
    BEFORE UPDATE ON chats FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

## 6. Additional Models (Beyond Master Document)



### 6.1 AgentMessage (internal)

Internal messages between agent nodes during a single request.

```python
class AgentMessage:
    id: UUID
    chat_id: UUID
    request_id: str  # correlation ID for the streaming request
    node_name: str  # e.g., "VacancyParserNode"
    event_type: AgentEventType
    payload: dict  # JSONB (node-specific data)
    created_at: datetime

class AgentEventType(Enum):
    STEP_STARTED = "step_started"
    STATUS = "status"
    ASSISTANT_DELTA = "assistant_delta"
    ARTIFACT_CREATED = "artifact_created"
    DONE = "done"
    ERROR = "error"
```

**Purpose:**

- Stores the full agent execution history for debugging and replay.
- Each row corresponds to one SSE event.
- `request_id` groups messages for a single streaming request.

**Relationships:**

- Many → `Chat`.
- Used by admin dashboard for agent diagnostics.

## 7. Design Decisions



### 7.1 Why separate `Vacancy` entity?

The parsed vacancy data (company, stack, skills, etc.) is used across multiple operations:

- Context retrieval (`ContextRetrieverNode`)
- Question generation (`QuestionerNode`)
- TeX generation (`GeneratorNode`)

Storing it separately avoids re-parsing and allows users to see/edit the parsed data.

### 7.2 Why `AgentMessage` separately from `Message`?

`Message` stores the conversation between user and AI (user-facing).
`AgentMessage` stores the internal agent workflow (diagnostic, SSE events).

This separation allows:

- Clean user-facing chat history.
- Detailed agent diagnostics without cluttering the chat.
- SSE replay for debugging streaming issues.



### 7.3 Why JSONB for `parsed_data`?

Vacancy data is semi-structured — different vacancies have different fields. JSONB allows:

- Flexible schema (company, location, salary, etc.).
- Fast queries (PostgreSQL GIN indexes on JSONB).
- Easy updates without schema migrations.



### 7.4 Why `minio_path` instead of storing content in Postgres?

Per ADR-003, blob storage keeps Postgres lean. The `minio_path` references the actual content in MinIO.
